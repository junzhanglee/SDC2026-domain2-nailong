# ParcelRelay

**快递到公司，不代表内部责任已经交接清楚。**

ParcelRelay 把到件关联到采购单或客户事项，按企业授权和人员状态推荐接收人，经人工审核、交出方确认与接收方复核后完成内部交接，并留下活动记录。

本仓库实现 2026-10-23 定稿任务书的比赛 MVP。原 Apache-2.0 许可证保留。**仅合成数据，身份可自由切换；这是演示环境，没有生产认证。**

## 立即运行

需要 **Node.js 24 或更新版本**。无需安装第三方依赖、申请 API key 或配置数据库服务。

```sh
npm start
```

打开 http://localhost:3000 。首次启动自动创建 SQLite 数据库和合成企业、人员、业务及 A/B/C 三条到件。停止再启动不会清空数据。

```sh
npm test
```

自动测试使用独立的内存或临时数据库，不修改你的验收数据。

可选环境变量：`PORT`（默认 3000）、`HOST`（默认 127.0.0.1）、`DATABASE_PATH`（默认 `data/parcelrelay.sqlite`）。实际数据库默认不提交 Git。Replit 配置会将 HOST 设为 0.0.0.0。

## 你如何验收

进入网站的「验收与说明」，按 A → B → C → D → E 操作。右上角切换合成企业、模拟身份；详情页也提供下一角色的切换按钮。

| 案例 | 要看到的结果 |
| --- | --- |
| A：采购到件 | 林悦确认 PO-2026-001 → 黄安休假，推荐李宁 → 陈美写理由批准 → 交出方确认 → 李宁核对显示器 M27 × 2 并接收 → 证明和日志；采购事项仍在进行中 |
| B：保密合同 | 林悦、陈美、李宁和普通配置负责人看不到受限收件或业务；周晨可核对 CT-2026-001；两名授权接收人缺席，只能暂存、升级或退回 |
| C：归属歧义 | 晨光出现两个候选；没有准确业务编号或明确确认就不能生成方案 |
| D：批准后撤权 | 许岑独立撤销 PO-2026-001 / 李宁接收授权后，李宁尝试接收被服务端拦截；恢复授权后仍需重新生成方案、审核及交出确认 |
| E：实物不符 | 报告数量或型号异常会暂停交接并清除批准；不能直接重新批准，须说明修正后重新生成方案 |

验收案例会保留结果。想重走 A/D/E 可在「到件登记」选择对应合成案例，修改唯一收件编号后保存，不需要清空数据库。完成 D 后请在企业规则恢复李宁接收授权，避免影响后续采购演示。

第二家企业「青杉会计事务所」提供 AC-2026-001 及独立人员配置，复用同一流程。这里只验证配置复用及接口范围过滤，不能视为已经实现生产多租户隔离。

## 已实现

- 工作台状态筛选、搜索、当前身份待办与合成案例表单；响应式桌面/手机页面。
- 到件登记、企业内唯一编号、缺字段与类型校验；采购物资、工作用品、客户资料与保密文件配置。
- 可解释业务候选、准确编号人工确认、原负责人/授权备用人推荐；无人可接收时暂停。
- 业务指定审核人批准、在已有授权范围内改派、退回、暂存、升级；理由与方案版本记录。
- 交出方和获批准接收人分别以自己的模拟身份确认，证明项缺失不能完成。
- 服务端 SQLite 事务内执行前复核、一次性状态转换及过期页面保护；重复请求不会重复交接。
- 关键资料/授权/相关人员状态变化使旧批准失效；无关备注保留批准。
- 企业范围和保密可见性检查覆盖列表、候选、操作与 JSON 导出。
- 活动记录包含事件编号、操作者、角色、MYT 展示时间、前后状态、理由、方案版本和结果。
- SQLite 持久化；可见记录导出；企业授权与可用性独立变更并留记录。

## 明确的演示边界

- 身份通过 `X-Demo-Company` / `X-Demo-User` 模拟，用户可任意选择；**不能上传真实数据或宣称是真实认证与生产安全**。
- 所有 Orbyte 员工、可用性、角色、授权与业务数据均是团队合成接口假设，未完成 Orbyte 接入。
- 没有 AI 模型调用、WhatsApp、邮件或外部通知。规则输出明确标为规则，待办只在站内展示。
- 交接不代表合同审阅、资料审核、采购使用或后续业务办结；不作专业法律/财务判断。
- 数据库和日志由本机拥有者控制，可直接修改；不具备防篡改、云备份或真实双因素签收能力。
- 配置负责人只管理可见公开业务的接收授权；保密授权范围保持固定，不提供无边界扩权。
- 尚无真实客户访谈、商业收益、受控用户实验或官方提交验收结果。不得把自动测试或合成演示写成市场实测。
- 还没有验证 Replit 线上运行、部署、录像或最终提案；详情见 `docs/验收记录.md`。

## 文件与说明

```text
public/          页面、交互与响应式样式
lib/domain.js    角色、业务关联、审核、版本、异常及交接规则
lib/store.js     SQLite 持久化、迁移与事务
server.js        HTTP 接口与范围检查
server.test.js   真实 HTTP + SQLite 行为测试
方案与初赛验收.md  定稿产品任务书（保留原文，不代表所有阶段已完成）
docs/            接口假设、验收记录和原始用户测试模板
```

SQLite 使用单行 JSON 状态快照，并在 `BEGIN IMMEDIATE` 事务中读、校验和写入；适合此小规模合成演示。后续需要查询、并发扩展、数据库授权与不可修改审计时，应迁移为规范化数据表和正式身份体系。

## 当前界面：按步骤处理

工作台默认显示「待我处理」。进入收件后，一次聚焦当前步骤；完成后按页面的人名与操作提示继续。收件资料、推荐依据与活动记录在页面下方按需展开。右上角「模拟身份」菜单保留全部角色与企业选择。
