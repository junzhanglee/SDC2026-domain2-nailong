# ParcelRelay

**快递到公司，不代表内部责任已经交接清楚。**

ParcelRelay 是移动端优先的个人任务网页：每位成员用自己的账号登录，查看自己的待办，完成当前步骤后由下一位同事接续。纯白主题、深色文字、底部导航、轻量页面过渡和完成反馈；不再提供登录后的名字或角色切换。

依据：2026-10-23 定稿《方案与初赛验收.md》。保留原 Apache-2.0 LICENSE。当前业务与试用人员均为合成数据。

## 启动和测试

需要 Node.js 24+，无第三方依赖、AI key 或独立数据库服务。

```sh
npm start
npm test
```

访问 http://localhost:3000 。首次启动自动建立合成企业、人员、业务、到件、密码散列与会话表。重启不会重置数据或已修改的密码。测试使用独立内存/临时数据库，不修改验收数据。

可选环境变量：`PORT`（3000）、`HOST`（127.0.0.1）、`DATABASE_PATH`（data/parcelrelay.sqlite）、`COOKIE_SECURE=1`（仅 HTTPS 部署时启用 Secure cookie）。Replit 配置提供 0.0.0.0 和 3000 端口；尚未验证线上运行。

当前是本机运行的移动网页，已经检查手机尺寸布局；其他手机要共同访问，需要部署可访问的服务地址。这不是已经发布到应用商店的原生 App。

## 验收一条完整任务

使用不同手机/浏览器会话分别登录，可模拟多人协作。在同一浏览器验收时，需要退出后再输入另一个账号及密码；不能点击名字代替其他人。

1. **林悦登录**：打开一条待核对采购收件，或在「登记」填充案例 A；确认 `PO-2026-001` 与收件信息一致。生成推荐李宁的方案后，该审核任务进入陈美的待办。
2. **陈美登录**：在自己的任务中打开该收件，写明理由并批准。交出任务进入林悦的待办，陈美不能替林悦确认交出。
3. **林悦登录**：确认实际交出。接收任务进入李宁的待办。
4. **李宁登录**：核对显示器 M27 × 2、状况与实际接收。完成后显示双方姓名、时间和交接证明；采购业务仍为进行中。

自己的待办、跟进记录和已完成记录分开显示，前台任务页在可见且未编辑时定时读取最新状态。刷新与服务重启后记录仍保留。想重走流程，请登记新的唯一收件编号。

## 异常验收

- **B 保密**：周晨登录核对 CT-2026-001。温岚、何皓均不在岗，不能将保密件分给普通员工；选择暂存、升级或退回。普通账号看不到受限元数据。
- **C 歧义**：晨光出现两个业务候选，必须输入准确编号并明确确认；名称不自动确定归属。
- **D 条件变化**：批准后，许岑在「我的 → 企业授权与规则」独立撤销 PO-2026-001 / 李宁接收授权。李宁执行接收时被拦截，旧批准失效并记录原因。恢复授权后仍需重新规划、审核及交出确认；验收后请恢复该权限。
- **E 实物不符**：接收人报告型号/数量异常后，交接暂停、批准清除。记录修正情况并重新生成方案后才可重审。不能跳过必要证明或重复领取。

## 成员和账号

企业配置负责人可在「我的 → 成员账号」创建成员账号。新成员岗位不会自动授予业务权限：

- 新登记员：在企业设置中独立配置「业务查看与登记关联」。
- 新审核人：独立配置「授权审核」，且必须属于审核岗位。
- 新接收人：独立配置已有的「接收授权」。

权限变更必须说明理由、独立记录；普通配置负责人不能扩展保密业务授权。成员可在自己的「我的」页面修改密码；改密使旧会话失效。

## 登录与任务边界

- 密码采用独立随机盐和 scrypt 散列保存；会话为高熵随机值，数据库只存 token 摘要。
- 会话使用 HttpOnly、SameSite=Strict cookie，12 小时有效；支持当前设备退出、改密时撤销旧会话、登录失败节流。
- 所有变更要求 JSON 并检查来源；服务端重新确认会话与权限。旧 `X-Demo-User` / `X-Demo-Company` 不再提供任何身份能力。
- 服务端生成当前账号的任务清单；关键动作校验实际登录者、业务授权、指定交出方与接收人。
- SQLite 事务内执行前复核、版本和过期页面保护，防止并发重复交接。活动记录可见范围与收件一致。

这仍是带公开试用账号的合成比赛环境，不代表完整生产安全。未实现验证码/SSO、找回密码、MFA、完整账号停用/邀请生命周期、云备份和不可修改审计；上线前还需生产认证与部署审查。不要导入真实员工、合同或客户资料。
