# 接口与数据假设

本文件描述团队自建 MVP 接口，**不是 Orbyte 的已发布接口文档**。

## 身份和范围

除静态页面、健康检查和模拟身份清单外，读取/变更请求必须带 `X-Demo-Company`、`X-Demo-User`。服务端校验该用户属于当前企业，再按角色和具体业务授权过滤。身份可任意切换，仅用于合成演示，不提供真实身份保证。

普通配置负责人不能通过配置接口读取或扩展保密业务接收授权；普通主管不因职位自动获得保密查看权限。公开业务撤销接收授权后保留查看权限，使原接收人能看到暂停与拒绝原因。

## 自建 HTTP API

| 接口 | 行为 |
| --- | --- |
| GET /api/health | 本地运行状态、合成模式、SQLite 存储说明 |
| GET /api/bootstrap | 合成企业和模拟身份清单 |
| GET /api/state | 当前身份可见的工作台、业务配置和活动记录 |
| GET /api/parcels | 当前身份可见收件 |
| GET /api/candidates?q=…&type=… | 名称/编号候选及依据；过滤受限业务，不自动关联 |
| GET /api/export | 只导出当前身份可见数据及导出时间 |
| POST /api/parcels | 登记；校验来源、收件人、类型、编号、重复和期限格式 |
| POST /api/parcels/:id/link | 确认准确业务编号与类型，生成带版本的分派方案 |
| POST /api/parcels/:id/review | 指定审核人批准、改派、暂存、升级或退回，必须有理由 |
| POST /api/parcels/:id/release | 在岗且获准处理的交出方确认交出；重新检查批准 |
| POST /api/parcels/:id/handoff | 获批准接收人确认必要证明；事务内复核并一次性交接 |
| POST /api/parcels/:id/exception | 报告实物/资料异常，暂停并清除批准 |
| POST /api/parcels/:id/replan | 说明条件修正，再生成新版本方案；必须重新审核 |
| POST /api/parcels/:id/edit | 无关备注保留批准；关键资料变化使批准失效并要求重新核对 |
| POST /api/config | 配置负责人独立记录接收授权或人员状态变更及理由 |

POST 使用 JSON；各收件动作带 `etag`，审核/交出/接收还带当前 `version`。旧页面返回 409，客户端刷新后再操作。JSON 无效、字段缺失和证明不全返回 400；无权操作返回 403；不可见收件统一返回 404，避免透露对象是否存在。

## 方案有效性与持久化

批准绑定方案版本和关键条件指纹：收件关键资料版本、业务/授权规则版本、相关授权人员在岗状态版本。领取时同时检查当前状态、批准、接收授权、人员在岗状态、交出方确认、证明项及是否已交接。

条件变化产生的拦截会持久化新方案和拒绝原因，返回 409，不能只把按钮隐藏。SQLite 写事务覆盖读取、判断和结果保存；两个同时到达的领取请求只能产生一个完成事件。无关备注不增加关键资料版本。

预置到件及企业配置来自团队合成资料；未来可在 Orbyte 实际开放接口和授权明确后替换数据源。当前没有网络连接、真实通知、AI、真实合同内容或法定期限计算。
