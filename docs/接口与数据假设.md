# 自建接口与数据假设（当前个人账号版本）

这些是团队自建 MVP API，不是 Orbyte 已发布接口。所有业务内容与试用人员均为合成数据。

## 个人账号

POST /api/auth/login 验证账号密码后签发 12 小时 HttpOnly / SameSite=Strict 会话 cookie。会话固定绑定一个企业和用户；服务端不接受 X-Demo-User、X-Demo-Company 或请求体人名作为身份。数据库分别保存 scrypt 密码散列与会话 token 的 SHA-256 摘要，不将明文密码或会话写入业务 JSON。

仅页面、健康检查、合成试用账号帮助和登录不需要会话。试用账号初始凭据公开用于合成演示，修改后的密码和新建成员凭据不会公开。

| API | 用途 |
| --- | --- |
| GET /api/auth/me、GET /api/state | 当前账号、其参与的收件/可见业务、任务标记、活动记录 |
| POST /api/auth/login | 密码登录，失败节流；账号/密码错误使用相同提示 |
| POST /api/auth/logout | 撤销当前设备会话，清 cookie |
| POST /api/auth/password | 核验旧密码、更新散列、撤销旧会话并重新签发当前会话 |
| GET /api/demo-accounts | 仅返回固定合成试用账号及其初始凭据 |
| GET /api/accounts、POST /api/accounts | 当前企业配置负责人查看和创建成员；返回数据不含密码散列 |
| GET /api/tasks | 服务端计算的当前账号待办，非前端自行按角色筛选 |
| GET /api/parcels、GET /api/export | 当前账号参与且仍获准查看的收件/记录 |
| GET /api/candidates?q=…&type=… | 可见业务候选和匹配依据，不自动关联 |
| POST /api/parcels | 登记；企业内唯一编号、字段与类型校验 |
| POST /api/parcels/:id/link | 责任登记员或保密业务指定审核人核对准确编号与类型 |
| POST /api/parcels/:id/review | 业务指定审核人批准、在已有授权内改派、暂存、升级或退回 |
| POST /api/parcels/:id/release | 指定交出方用自己的会话确认交出 |
| POST /api/parcels/:id/handoff | 获批准接收人逐项核对；事务内复核并一次性完成 |
| POST /api/parcels/:id/exception | 获准处理者报告异常、暂停交接并使批准失效 |
| POST /api/parcels/:id/replan | 说明修正情况并生成新方案；须重新审核 |
| POST /api/parcels/:id/edit | 无关备注保留批准，关键资料变化使批准失效 |
| POST /api/config | 配置负责人独立修改公开业务查看/审核/接收权限或人员在岗状态，要求理由 |

## 个人任务流转

登记归属核对属于登记者；保密件交给指定授权审核人。确认业务后由业务审核名单中的人员审核。批准时指定交出方：优先在岗且获准处理该业务的原登记者，否则使用允许处理的在岗审核人；不得将任务仅按角色广播给所有人。交出方完成后，接收任务才进入被批准接收人的待办。

审核名单可配置多位审核人时，他们共同具备处理资格；任何一人完成后，该步骤不再出现在其他人的待办。任务和版本状态在服务端生成与更新。个人页面分为待我处理、跟进中、已完成；完成自己的步骤不等于整个收件已交接。

公开收件在仍具业务查看权的前提下，向创建者、指定审核者、获分派接收者与参与者展示。保密收件另需保密业务明确读授权，不因岗位名称扩权。管理员新建账号只赋予岗位身份，不自动获得任何业务审核/接收授权。

## 校验与保存

POST 使用 JSON。收件操作带 etag，审核/交出/接收带当前方案 version。401 表示没有有效会话；403 表示当前账号无操作权；404 统一表示收件不存在或不可见；409 表示状态/版本冲突或执行条件失效。

批准绑定关键资料、业务规则/授权版本和相关人员状态。执行时检查当前批准、接收人授权、双方身份、交出证明、必要核对和是否已交接；SQLite BEGIN IMMEDIATE 事务覆盖读取、判断和写入。关键条件变化产生的拦截及新方案会持久化。无关备注不增加关键资料版本。

业务使用单行 JSON 快照，账号、会话、节流使用独立 SQLite 表；适用于小规模比赛演示，不声称为完整生产多租户或防篡改审计。
